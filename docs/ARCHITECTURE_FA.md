# معماری پروژه

## جداسازی Frontend و Backend

پروژه عمداً به دو بخش مستقل تقسیم شده است:

```text
SDL Event + SDL Renderer
          |
          v
       StudioApp
          |
          v
Circuit / Component / Wire / Junction
          |
          v
SimulationEngine
```

هیچ کلاس هسته‌ای SDL را Include نمی‌کند. در نتیجه منطق مدار بدون باز شدن پنجره قابل کامپایل و تست است. رابط SDL فقط وضعیت مدل را می‌خواند، آن را رسم می‌کند و عملیات کاربر را به تغییرات مدل تبدیل می‌کند.

## هسته مدار

`Component` کلاس پایه انتزاعی تمام قطعات است. هر قطعه موارد زیر را از این کلاس دریافت می‌کند:

- شناسه یکتا و Label
- موقعیت، زاویه و حالت Mirror
- فهرست Pinها
- Propertyهای قابل ویرایش
- Runtime State
- رابط‌های مجازی تحلیل آنالوگ و دیجیتال

کلاس‌های مشتق‌شده رفتار واقعی قطعات را با Override کردن متدهای زیر تعریف می‌کنند:

- `stampAnalog`
- `acceptAnalogResult`
- `evaluate`
- `resetRuntime`
- `validationError`

کلاس `Circuit` مالک قطعات است و Ownership با `std::unique_ptr` انجام می‌شود. سیم‌ها و Junctionها نیز داخل همین کلاس نگه‌داری می‌شوند. حذف یک قطعه باعث حذف سیم‌های وابسته و به‌روزرسانی Junctionها می‌شود.

## موتور آنالوگ

تحلیل آنالوگ بر اساس Modified Nodal Analysis انجام می‌شود. قطعات ماتریس را مستقیم دست‌کاری نمی‌کنند؛ آن‌ها Stampهای مستقل تولید می‌کنند:

- Conductance Stamp
- Current Stamp
- Voltage Source Stamp
- Ground Mark

موتور پس از جمع‌آوری Stampها، دستگاه خطی را حل می‌کند و ولتاژ Netها و جریان شاخه‌های منبع را در اختیار قطعات و ابزارها قرار می‌دهد.

برای Capacitor و Inductor از مدل گام زمانی استفاده شده است. مقدار گام قبلی در Runtime State نگه‌داری می‌شود تا رفتار زمانی قطعه حفظ شود.

## موتور دیجیتال

مقادیر دیجیتال همچنان ولتاژ دارند و سه حالت منطقی از آن‌ها استخراج می‌شود:

- `LOW`
- `HIGH`
- `Undefined`

تغییرات خروجی قطعات در صف اولویت رخدادها قرار می‌گیرند. هر رخداد زمان سررسید و شماره ترتیبی دارد. به این روش Propagation Delay مستقل از نرخ رسم پنجره باقی می‌ماند.

گیت‌ها Undefined را منتشر می‌کنند و هشدار `Floating input detected.` در Log ثبت می‌شود. D Flip-Flop فقط لبه بالارونده Clock را تشخیص می‌دهد.

## Net و Junction

پایه‌هایی که با Wire متصل‌اند با Disjoint Set در یک Net قرار می‌گیرند. تقاطع گرافیکی دو سیم به‌تنهایی اتصال نیست. فقط وجود شیء `Junction` باعث Union شدن Netهای دو سیم می‌شود.

این تصمیم دقیقاً تفاوت «عبور دو سیم از روی هم» و «اتصال واقعی» را مدل می‌کند.

## رابط SDL

`StudioApp` مالک چرخه اجرای برنامه است:

1. دریافت `SDL_Event`
2. تبدیل مختصات Screen و World
3. اعمال عملیات روی Model
4. پیش‌برد Simulation Time
5. رسم کامل Frame

رندر متن توسط فونت Bitmap داخلی انجام می‌شود. بنابراین SDL_ttf لازم نیست. نماد تمام قطعات نیز به‌صورت برداری با Line، Rect و Circle رسم می‌شود.

`Geometry.cpp` مسئول موارد زیر است:

- تبدیل مختصات
- اندازه قطعه
- تعیین موقعیت Pinها
- Hit Test
- ساخت مسیر ۹۰ درجه Wire

`Input.cpp` رویدادهای ماوس و کیبورد را مدیریت می‌کند و `Render.cpp` فقط وظیفه رسم دارد. این تفکیک باعث می‌شود منطق تعامل و نمایش در هم مخلوط نشوند.

## Save/Load و Undo/Redo

پروژه در JSON متنی ذخیره می‌شود. Serializer مستقل از SDL است و موارد زیر را حفظ می‌کند:

- تنظیمات بوم
- قطعات و Propertyها
- موقعیت، Rotate و Mirror
- Wire و Waypoint
- Junction
- Runtime State
- Flash میکروکنترلر
- زمان و حالت شبیه‌سازی

برای حذف وابستگی اضافی، Parser/Writer کوچک JSON در خود پروژه نوشته شده است.

Undo/Redo از Snapshotهای JSON در حافظه استفاده می‌کند. هر Mutation موفق یک Snapshot جدید می‌سازد. اگر بعد از Undo تغییر جدیدی انجام شود، شاخه Redo قبلی حذف می‌شود.

## DRC

پیش از Run موارد زیر کنترل می‌شوند:

- خالی نبودن مدار
- وجود GND
- معتبر بودن Propertyهای قطعات
- Floating Input
- ورودی دیجیتال متصل ولی بدون Driver
- Wire با Endpoint نامعتبر
- چند خروجی قوی یا چند منبع روی یک Net

وجود Error مانع Run و Step می‌شود. نتیجه در Simulation Log نمایش داده می‌شود.
